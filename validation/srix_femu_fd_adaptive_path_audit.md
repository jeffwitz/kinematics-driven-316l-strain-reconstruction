# Audit — archived FEMU FD versus the base accepted path

The archived `FEMU_observed` Jacobian was generated by calling the adaptive
forward driver independently for every `+h/-h` parameter perturbation. The
macro endpoints are the same, but the adaptive controller is part of the
numerical trajectory and is not parameter-invariant.

The following checks were run on the M8 twin with `h=3e-3`, without P43:

| trajectory | accepted increments | scored accepted indices |
|---|---:|---|
| base | `338` | `4, 36, 125, 275, 312, 316, 326, 338` |
| `Q+` | `326` | `4, 31, 122, 266, 312, 318, 322, 326` |
| `Q-` | `328` | `4, 14, 92, 234, 315, 320, 324, 328` |

The macro fractions remain `0.125, 0.25, ..., 1.0`, but the internal
sub-increments and their constitutive commit points differ. Therefore the
archived finite difference is not a derivative at a fixed discrete load path;
it also contains the response of the adaptive stepping policy. A tangent
sensitivity propagated on the accepted base path cannot be expected to equal
that object.

The direct sensitivity gate must consequently compare against a second FD
oracle in which the base accepted `LoadPathStep` sequence is frozen for both
signs. The archived adaptive FD remains a useful separate diagnostic, but it is
not the primary equality gate for the tangent-linear method.

Machine-readable values are recorded in
`validation/reference_data/srix_femu_fd_adaptive_path_audit/report.json`.
